Group	5 = 4 + 1	Read + execute

Ye ek important defensive instruction hai.
-e — Exit on unhandled command failure
Shell kuch command failures par script ko stop kar deta hai, instead of blindly continuing.
Example:

Agar compilation fail hui, script ko executable run karne ki koshish nahi karni chahiye.

11. timeout command
timeout \
    --signal=TERM \
    --kill-after=1s \
    "${timeout_seconds}s" \
    /tmp/program


Definition — Execution timeout: Maximum permitted time jiske baad system program ko terminate karne ki koshish karta hai.
Soch, student ka program infinite loop mein phans gaya:
int main() {
    while (true) {}
}


Agar time limit nahi hai, program CPU consume karta rahega. Online judge ko aise execution ko stop karna padta hai.
Har option ka meaning:
- timeout: GNU Coreutils ka command jo duration limit ke saath process execute karta hai.
- --signal=TERM: Deadline par pehle SIGTERM bhejo, jo process ko terminate karne ka request hai.
- --kill-after=1s: Agar process ek second ke andar terminate nahi hota, toh stronger SIGKILL bhejo.
- "${timeout_seconds}s": Time limit, jaise 3s.
- /tmp/program: Execute hone wala binary.
Python ke case mein timeout isi tarah interpreter aur uske script par apply hota hai:
timeout 3s python3 "$source_file"


SIGTERM vs SIGKILL
SIGTERM — Graceful termination request
Process ko terminate hone ka signal milta hai. Program signal handle kar sakta hai, cleanup kar sakta hai, ya signal ignore kar sakta hai.


SIGKILL — Forced termination
Process is signal ko catch ya ignore nahi kar sakta. Operating system process ko forcibly terminate karta hai.


timeout ke alternatives
Approach	Kab useful hai?	Limitation
GNU timeout	Simple per-process deadline	Descendant processes aur full resource isolation ko separately handle karna pad sakta hai
Node.js child_process timeout	Existing Node executor mein	Process-tree termination aur cleanup carefully implement karna hoga
Docker/container runtime deadline	Container-level execution control	Container ko reliably stop/kill aur cleanup karna hoga
External watchdog	Worker ya supervisor process se execution monitor karna	Extra orchestration complexity
Ek critical implementation detail: Is script mein timeout sirf execution command ko wrap karta hai. C/C++ compilation ko abhi timeout se wrap nahi kiya gaya. Isliye malicious ya pathological source se compilation bhi excessive time ya memory consume kar sakti hai. Production implementation mein compile aur run dono ke liye resource controls chahiye.
12. exec ka actual role
exec timeout ... /tmp/program


Definition — exec: Shell ke current process ko specified command se replace karta hai.
exec ke bina shell ek child process launch karke uske finish hone ka wait kar sakta hai. exec use karne par shell ki separate process layer replace ho jaati hai.
Isse process management aur signal forwarding simpler ho sakte hain.
Alternative: exec ke bina command chalana aur shell ke through status handle karna. Ye tab useful hai jab script ko command ke baad cleanup, logging ya custom exit-code mapping karni ho.
CodeArena mein aage humein compilation aur execution ke exit statuses distinguish karne honge. Isliye production runner mein sirf exec kar dena sufficient nahi; humein exit codes aur timeout status ko explicitly capture karna padega.
Timeout ka exit code kya hota hai?
GNU timeout normally deadline par terminate karne ke baad exit code 124 return karta hai. Agar process ko force-kill karna pade toh 137 bhi dikh sakta hai.
Lekin exit code 137 ko automatically OOM verdict mat samajhna. Ye SIGKILL se bhi aa sakta hai. Timeout, OOM aur manual termination ko distinguish karne ke liye watchdog state aur container/cgroup ki memory information bhi inspect karni hogi.
Online judge mein in internal statuses ko appropriate verdicts mein map kiya jaata hai:
- Accepted
- Compilation Error
- Runtime Error
- Time Limit Exceeded
- Memory Limit Exceeded
- Wrong Answer
Hamari current run.sh ye complete verdict classification implement nahi karti. Ye abhi ek basic execution runner hai.
